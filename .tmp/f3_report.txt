Ф3: расписание и запись — отчёт
================================
Сделано (платформа/, Node-слой, без UI, без зависимостей):
- db/schema.sql: lessons +duration_min, +created_at, CHECK на status; lesson_enrollments +booked_by (кто записал), +status active/cancelled, +cancelled_at; индекс слотов; права: slots.create (преподаватель), lessons.enroll/cancel (ученик), child_lessons.cancel (родитель), lessons.cancel/read_all (владелец).
- src/access.ts: enroll() переписан (право → «своё» → согласие до 16 → урок есть/не отменён/не в прошлом → без дубля), cancelEnrollment(); audit/guard экспортированы; запросы "ученики урока" учитывают только active.
- src/schedule.ts: requireActor (роль из БД по токену сессии), createSlot, enrollMe, cancelMine, myLessons (свой запрос на каждую роль, без контактных колонок).
- test/schedule.test.ts: 10 тестов (а-д, е1-е4, журнал). test/seed.ts: даты уроков 2099 (чтобы старые тесты не сгнили со временем).
Итог npm test: tests 26, pass 26, fail 0 (старые 16 зелёные + 10 новых).

Поломки (каждая — откат, затем 26/26):
M1 преподаватель видит чужие уроки -> красный (а)
M2 родитель записывает чужого ребёнка -> красные (в), журнал
M3 ученик видит чужие записи на своём уроке -> красный (б)
M4 родитель видит всех учеников урока -> красный (в)
M5 просроченная сессия принимается -> красные (д) + старый auth-тест
M6 пересечение слотов не проверяется -> красные (е2), журнал
M7 запись в прошлое -> красный (е3)
M8 двойная запись -> красные (е1), журнал
M9 нет проверки согласия до 16 -> красные (е4) + старый тест согласия
M10 ребёнок до 16 записывает себя сам -> красный (е4)
M11 email в запросе учителя -> красные (а), (г)

Слабые места:
- Нет лимита группы (до 6/8 — развилка 4) и вместимости слота.
- Пересечения у ученика (два урока в одно время) не проверяются; только у преподавателя.
- Гонки: SQLite однопоточный, транзакций вокруг проверка+вставка нет; в Postgres нужны транзакция и уникальные/exclusion-ограничения.
- Время в UTC; часовые пояса и «окно отмены» (за сколько часов) не реализованы.
- Отмена слота преподавателем / замена преподавателя не реализованы.
- Возраст считается по birth_date из базы; если даты нет — как ребёнок.
- Миграции нет как отдельного механизма: схема применяется целиком на пустой базе (как в Ф1/Ф2); для живой базы нужен ALTER-скрипт.
- Нет Postgres+RLS, как и раньше.
