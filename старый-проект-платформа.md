## 4. Безопасность и доступы
- Матрица «роль → защищённое поле», запрет по умолчанию: контакты семьи, платежи семьи, полный профиль ребёнка, учебное досье, кошелёк преподавателя, метрики бизнеса, очередь заявок, сигналы беды. Преподаватель имеет ТОЛЬКО учебное досье + кошелёк; методист — ничего из этого; admin — всё кроме платежей семьи и кошелька; owner и developer — всё. [П]src/lib/access.ts
- Роли: parent, teacher, methodist, admin, owner, developer (супер-набор владельца для разработчика). Роль «куратор» из спеки сознательно не заведена. Роли «ученик» нет. [П]src/lib/access.ts; [ПС §3.2]
- Закрытая база клиентов: контакты — только contact_vault; все остальные таблицы помечены в комментариях «контактов нет», это зафиксировано тестами схемы. Список учеников преподавателя строится запросом, в котором контактных колонок физически нет (не «спрятано в JSX»). [П]src/db/schema.ts, schema-class.ts, schema-teacher.ts; [П]src/lib/teacher/dashboard.ts
- Имя ребёнка у преподавателя — только displayName (имя без фамилии). [П]src/db/schema.ts
- Роль «учитель» назначает ТОЛЬКО сервер: найм → одобрение → setUserRole (самоназначение закрыто, input:false). [П]src/lib/hiring/promote.ts; auth-config.ts
- Вход в комнату: проверка принадлежности сессии (закрыт IDOR, аудит 11.07). [П]src/lib/class/access.ts
- Ребёнок: свой профиль доступен по сквозной проверке «ребёнок принадлежит семье этого родителя»; проверка формата UUID до запроса. [П]src/lib/kid/access.ts
- Оплата: идемпотентность вебхука (замок — вставка события), возврат живыми деньгами 28 дней, защита от двойной компенсации (найдено судьями), уникальные индексы на «один возврат на бронь» и «одно списание на урок+ребёнка». [П]src/lib/billing/{webhook-handlers,refund}.ts; src/db/schema-billing.ts; [П]src/db/schema-billing.ts
- Кроны закрыты секретом (сравнение за постоянное время; без секрета — 503). [П]src/app/api/cron/guard.ts
- Аварийные выключатели на Stripe(новые оплаты)/LiveKit/FAL/Anthropic: ключ остаётся, флаг гасит функцию. [КЛ §4; П src/lib/kill-switch.ts]
- Детские данные/безопасность: ИИ-чат ребёнка по умолчанию ВЫКЛЮЧЕН, включает родитель; модерация до/после; сигналы самоповреждения/насилия идут в отдельный экран /admin/safety, читают только admin/owner (поимённое закрытие). [П]src/db/schema-lumo-chat.ts; src/lib/lumo-chat/escalations.ts; src/lib/access.ts (safety_escalations)
- Записи уроков (задумано, не построено): согласие до записи, индикатор «идёт запись», удаление по запросу, видят только родитель/учитель/методист-владелец. [СБ §1]
- Гигиена: приватные кабинеты закрыты от индексации (robots). [ПС §3.1]
- Не закрыто (честно): RODO/GDPR-K не проработан; в памятке нет назначенного получателя красных флагов («нет-го» до первого ребёнка); юрлицо не оформлено. [ПС §6.3; СБ шапка]

## 5. Принятые решения (ADR и их аналоги)
Формальный ADR в проекте один; остальные решения разбросаны по шапкам кода и CLAUDE.md — указано, где.
1. Атомарность через batch-транзакции (`db.batch`), а не «транзакций нет»: прежняя посылка была ложной, доказано сравнением номеров транзакций; где следующий запрос зависит от предыдущего — условный UPDATE + уникальный индекс. Почему: на ложной посылке три недели строили деньги и награды. [ADR]
2. Схема базы катится push, без файлов миграций: быстрее при одном разработчике-агенте. Минус: два ручных списка файлов схемы (drizzle.config.ts и db/index.ts), забыть один = тихое «нет изменений». [ПС §2; Г 2026-07-16; П drizzle.config.ts]
3. Закрытая экосистема: контакты только в сейфе, всё общение/оплата/уроки внутри платформы, ни одной внешней ссылки клиенту. Почему: анти-увод учеников. [СП §2, §5; CM «Железные правила» стр.398]
4. Ребёнок не имеет логина — заходит через сессию родителя. Почему: нет поверхности для подбора кода, дешевле, шестая роль не нужна. [П]src/lib/kid/access.ts
5. Роль хранится в auth-таблице (для гейтов) и зеркалится в доменную; меняется одной точкой. Почему: баг «одобренный учитель остался родителем». [П]src/lib/auth-sync.ts, hiring/promote.ts
6. Копилка уроков — журнал движений, а не счётчик; уроки не сгорают; возврат 28 дней. Почему: главный «честные деньги» тезис. [П]src/db/schema-billing.ts; СП §1
7. LiveKit (видео) + Excalidraw (доска) вместо самоделок; H5P не берём (лицензия GPL, ломает правило «эталон ответа только на сервере»). [СП §3; ПС §6.11]
8. Все временные поля — только с часовым поясом. [CM стр.398–405]
9. Честная деградация: нет ключа = фича говорит «пока недоступно», не падает; плюс аварийные флаги. [КЛ §4; П livekit.ts]
10. Эталон ответа упражнения никогда не уходит на клиент; снимок задания замораживается при выдаче. [ПС §3.3]
11. Деплой только на Vercel, локальные тест-серверы не использовать. (процесс, можно не наследовать) [CM стр.8]
12. Мультиязычность pl/uk/ru/en с первого дня. [СП §2] (для новой школы язык интерфейса — решение владельца)
13. Вывод процесса: «тесты зелёные + сборка» ≠ готовность; нужны структурные тесты запросов, проверка чувствительности теста, живой прогон. [Г] 2026-08-02, 2026-08-19
